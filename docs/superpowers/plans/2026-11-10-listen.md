# @barmark/listen Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `@barmark/listen` 0.1.0, the one home of Stem Shovel's recording-to-chart math (features, onset comb, chartless grid and downbeat vote, chart alignment, fit, placements, timing map, whole pipeline), after two `@barmark/sync` releases: a patch that writes `[k/8]` pickups in compound meters, and a minor that adds `rehashTiming`.

**Architecture:** A port, not a rewrite: each app module becomes one stage module under `packages/listen/src/{features,comb,grid,align}/`, with the app's arithmetic in the app's order, every threshold threaded in from one resolved options object, and every throw or meaning-laden `null` turned into a named refusal (`Ok | Refused`, never a throw). `./features` imports nothing from `barmark` or `@barmark/sync`; `./stages` exposes each stage to the bench; the root exposes the four calls. A VM-only script runs the app's own modules (from a pinned, read-only copy of stem-shovel) beside the package and writes goldens that CI checks.

**Tech Stack:** Bun workspace, TypeScript strict (`exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`), Biome (tabs), `bun test`, Fallow; `barmark` and `@barmark/sync` as the only runtime dependencies.

**Spec:** `docs/superpowers/specs/2026-11-09-listen-design.md` (approved; §2 and §14 are Kevin's decisions and binding). Read it before any task: section numbers below (§N) are the spec's. Read-only port sources, in `~/projects/stem-shovel` (never write there, never run anything there): `src/lib/audio/{analysis,chartAlignment,alignmentRepair,chartlessGrid}.ts`, `src/lib/utils/{alignmentFit,alignedPlacements,alignedTimingMap,chordminiBarChords,barmarkChartBars,chordPitchClasses,tonicPitchClass,chartBarSeconds,meterBeats,median}.ts`, `src/lib/constants/chartAlignment.ts`, and their `*.test.ts`. ## Rulings on the spec (read with it)

These settle what the spec leaves open or what has moved since it was written. They are reported to Kevin with this plan.

1. **No compound-meter guard.** Task 1 ships sync's `[k/8]` pickups (sync 0.3.1) before listen exists, and listen 0.1.0 requires `@barmark/sync` ^0.4.0, which includes it. So the §7 guard is not built: listen reports compound-meter pickups like simple ones, and the `pickup-dropped` warning code and its §11.3 row are dropped.
2. **Seconds runs vote on the model's frame.** Since the spec was written the app's `chordminiBarChords` reads runs in seconds (no `frameSec`) on a frame of `2048 / 22050` s. `beatChords` ports that, not §11.1's "covered time": v1 is a port and the goldens come from the app.
3. **A chart without `time:` is 4/4**, as barmark reads it. The app's adapter substitutes the song's meter there (`meterRules`); `alignChart` does not (`declared` sets only the fit's bar, §6.3). This is a new §11.3 row; the equivalence charts all carry `time:`.
4. **Sections are headings, then rehearsal marks.** The app's third source, words that name a section (`chartSectionName`), is a score-read heuristic and stays in the app. New §11.3 row.
5. **A pickup that would put bar one at or past the end is not reported**: bar one stays at `a`, so `nothing-fits` means only that `a` itself is past the end.
6. **`startAt` pickups (byStart):** with `lead = barOne − firstSound`, nothing when `lead ≤ slack × beat`; `sound-before-start` when `lead ≥ period` or the beat count `j` (computed from `a = barOne − period`) is 0; otherwise a pickup of `beatsPerBar − j` beats at `max(0, a + j × beat)`.
7. **`chartFromRecording` takes samples or features, not both**: both given is `invalid-input` (`detail.field: "features"`), never one silently ignored.
8. **The equivalence script clones, it does not add a worktree.** `git worktree add` writes `~/projects/stem-shovel/.git/worktrees/`, which the brief forbids. The script uses `git clone --shared --no-checkout ~/projects/stem-shovel <dir>` and checks out the recorded commit detached; this reads stem-shovel only and gives the same isolation. Real mixes are compared in the script on the VM; CI's goldens cover the seeded synthetic songs (their PCM is regenerated in the test, so no audio is checked in).
9. **`?` and groups need no warning code of their own**: barmark already warns on every `?`, so `chart-diagnostics` (§4.2) carries it; a group playing its first member is documented in the README.
10. **`rehashTiming` compares meters by value** (`a.n × b.d === b.n × a.d`), as grammar 2.4 compares lengths, and counts confidence slots as `PlayedBar.slots.length` (top-level slots, a group one slot), the shape `ConfidenceRecord.bars[].slots` lines up with.

## Review Focus

1. **A cached features record that does not match what it claims** (another sample rate's record, a hand-edited `hopSec` or `fps`, plain arrays after a JSON round trip, an older `version`): a reasonable person expects a cache miss (`features-invalid` or `features-version`), never a map aligned on a mismatched hop. → Task 5 test "readFeatures refuses a record whose hop or fps does not follow from its rate".
2. **Chart tempo in odd places**: a chart whose first bars have no `tempo:` (a later bar sets it) with and without `AlignInput.tempo`, a `rit.` bar, a `time:` change mid-chart and a `[6/8]` bar in 4/4. Expected: fallback for the untempoed bars, `no-tempo` without it, the §6.3 seconds everywhere, no tempo change reported for the one-bar meter. → Task 10 test "bars before the first tempo take the fallback".
3. **Degenerate chord runs** (empty `runs`, a run with `NaN` or `Infinity` ends, overlapping runs, `frames` smaller than the last run's end, an unknown Harte label): the harmonic witness abstains or votes as the app does, nothing throws, and the pipeline still returns the builder's own diagnostics. → Task 7 test "degenerate runs never throw and abstain".
4. **A pickup clamped at 0:00** (the first sound in the first quarter beat of a recording whose lattice puts the pickup's start before zero): `pickup.start` is 0, sync re-derives a shorter pickup or ignores it (`pickup-ignored`), and the timing map still checks clean against the chart written, with as many entries as the chart plays bars. → Task 14 test "a pickup clamped at zero round-trips through the builder".
5. **A long recording whose grid is cut by `MAX_GRID_BARS`**: `grid-truncated` is warned, the chart has exactly that many bars, chords past the grid come back as sync's `outside-bars`, and the map checks clean. → Task 14 test "a truncated grid builds a chart that checks".
