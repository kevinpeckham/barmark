# @barmark/midi Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new package, `@barmark/midi`, in three shippable phases:

1. **Export** (`@barmark/midi` 0.1.0): `exportMidi` writes a format 1 Standard MIDI File that plays a chart's play order, built on a performance core published as `@barmark/midi/perform`. Useful alone; needs no barmark change.
2. **Import** (0.2.0): `importMidi` reads format 0 and 1 files into a canonical chord chart, naming chords from notes with a new barmark export, `nameNotes`, and writing the chart with `@barmark/sync`'s `chartFromDetections`.
3. **CLI** (`@barmark/cli` 0.7.0): `barmark export --midi` and `barmark import file.mid`.

**Architecture:**
- `packages/midi/src/perform/` is the subpath `@barmark/midi/perform`: `perform(parse)` turns `parseChart`'s played bars into tracks of timed notes, a tempo map, meters, keys, markers, words and lyrics, in exact quarter notes. It imports nothing from `smf/`, `export/` or `import/`.
- `src/smf/` is a hand-written SMF writer (Phase 1) and reader (Phase 2).
- `src/export/` turns a `Performance` into ticks, channels and tracks, and writes it.
- `src/import/` works in stages:
  1. read the file (`smf/read.ts`);
  2. pair notes and pick the harmony streams (`notes.ts`, `streams.ts`);
  3. make the bar grid and the key, meter and tempo changes (`grid.ts`, `directives.ts`);
  4. cut segments and name them (`segments.ts`, with barmark's `nameNotes`);
  5. hand bars, runs, markers and directives to `chartFromDetections` (`build.ts`);
  6. add lyric rows (`lyrics.ts`).

**Tech Stack:** Bun workspace, TypeScript strict, Biome (tabs), Fallow, `bun test`. Runtime dependencies: `barmark` (`workspace:^`, packed as `^0.20.0` for 0.1.0 and `^0.21.0` for 0.2.0), and from Task 13 `@barmark/sync` (`workspace:^`). DevDependency: `midi-file` at exactly `1.2.4`.

**Spec:** `docs/superpowers/specs/2026-11-08-midi-design.md`. It is binding: Kevin gave the go-ahead on its open questions as recommended, and the review's rulings are recorded there as "Claude's ruling, 2026-11-08". Every task reads the sections it names. The grammar draft is not changed.

## Global Constraints

- The package is `packages/midi`, published as `@barmark/midi`, MIT, `engines: node >=20`, `"sideEffects": false`. Exports `"."` and `"./perform"`. Tag prefix `midi-v`.
- `@barmark/midi/perform` imports nothing from `src/smf/`, `src/export/` or `src/import/`.
- **No runtime MIDI library.** `midi-file@1.2.4` (exact) is a devDependency, used only by tests.
- The types in spec section 2 are copied **verbatim**: `MidiExportOptions`, `MidiLossCode` (exactly the 7 codes), `MidiLoss`, `MidiExportResult`, `MidiImportOptions`, `MidiImportDiagnostic`, `MidiImportResult`, `Quarters`, `PerformedNote`, `PerformedTrack`, `Performance`. `MidiImportCode` is exactly the 23 codes of spec 5.9 (22 in the first draft; `lyrics-verses-uncertain` was added by the Task 14 review's ruling) plus sync's `BuildCode`.
- `exportMidi` never reads chart text itself: only `parseChart`/`extractPart` output. With chart errors it returns `{ ok: false }` and no bytes.
- `importMidi` **never throws**, whatever the bytes. Its `text` is `""` exactly when a diagnostic is an error; otherwise `text` parses with **no errors** and `printChart(text) === text`.
- **Channel 10** (index 9) is never written, and never read as harmony.
- Export is play order (`parse.bars`, fermatas from `parse.events`); import writes play order out (no repeats, endings, jumps or replays).
- Times in the performance are exact fractions of a quarter; ticks appear only in `src/export/`.
- Repo rules apply:
  - Test first: a failing test before every rule.
  - `bun test`, `bun run check` and `bun run fallow` stay green; the Fallow baseline doesn't grow.
  - Each user-visible change gets a CHANGELOG `[Unreleased]` entry (the midi package's, barmark's for `nameNotes`, the CLI's).
  - Each surprise gets a FINDINGS.md entry.
  - Commits are conventional, with **no** `Co-Authored-By` or AI trailer.
  - Changes reach `main` only by pull request with green CI.

## Review Focus

1. **Play order through everything the parser resolves.** A push across a bar line, back over a `:|`, after a jump; a replay with its own lyrics; `%` after a one-bar meter; a tacet part; an open repeat. The test player (Task 6) must hear what `parse.bars` says. Tests in Tasks 3, 6 and 7.
2. **Hostile bytes.** Truncated chunks, a header claiming 65,535 tracks, a chunk length of 0xFFFFFFFF, five-byte VLQs, a stray `F4`, a 10 MB sysex, a tempo of 0, a time signature of 7/3, 300,000 note-ons with no offs. `importMidi` never throws, stays within the bounds and stays linear. Tests in Tasks 9 and 13b.
3. **Hostile text** in track names, markers and lyrics: `"Intro\n| C |"`, `"## Coda"`, `"key: G"`, `"%"`, `"x2"`, `"\u001b[31m"`, `"a|b"`, `"{C}"`, `"_"`, `"--"`, `"/"`. The chart keeps its shape: the title is one line, a marker is one heading, a syllable is one syllable or nothing, and no control character reaches the chart. Tests in Tasks 13 and 14.
4. **MuseScore's own files.** Slash notes sounding as B3/B4, chord-symbol playback on its own channel, a melody with lyrics in track 1 beside the tempo map, a pickup as 1/4 then 3/4. Their charts carry the chords, not Cmaj7 for C. Test in Task 15.
5. **Channel exhaustion:** a chart of 6 parts with 4 lines each. At most 15 distinct channels, never index 9, one `channels-shared` loss. Test in Task 6.
6. **Scale:** a 1,000-bar chart exports, and a 9,000-bar, 180,000-note file imports (off the 10,000-bar bound, which counts a pickup), each linear (ten times the input at most twenty times as long, best of three). Tests in Tasks 7 and 13b.

## Claude's calls made in this plan

The spec leaves these open. Each is marked where it applies.

- **Quarters arithmetic** lives in `src/perform/quarters.ts` (`q(n, d)`, `add`, `sub`, `mul`, `cmp`, `toNumber`), a copy in spirit of musicxml's `rhythm.ts` `Frac`, not shared: packages don't import each other's internals.
- **The key signature count** is computed in `src/perform/keys.ts` (`keyFifths(key)`), and a test pins it to barmark's private `signature` in `packages/barmark/src/chart/keys.ts` by relative import (as musicxml's `played.ts` imports barmark's test fixtures). The test uses its own flats list (`Cb Gb Db Ab Eb Bb F`, with the naturals and sharps): barmark's `FLATS` isn't exported. Phase 1 then needs no barmark release.
- **`slotTimes` in quarters** (spec 3.4, Claude's ruling, 2026-11-08): `src/perform/quarters.ts` exports `slotQuarters(slots, meter)`, built on barmark's exported `memberShares`; a test pins it, slot for slot, to barmark's private `slotTimes` (relative import from `packages/barmark/src/chart/shares.ts`, × 4) over every bar of the corpus.
- **`perform` walks `parse.events`** itself (bars, fermatas, an open repeat's events once), not `parse.bars`, because fermatas aren't bars. A test asserts its bar list equals `parse.bars` index for index.
- **The test player** (`tests/helpers/player.ts`) reads bytes with `midi-file` only, never with our reader, so export and import can't share a mistake.
- **A readable SMF builder for tests** (`tests/helpers/smf.ts`): `smf({ format, ppq, tracks: Event[][] })` with events like `{ dt: 0, on: [0, 60, 80] }`, `{ dt: 480, off: [0, 60] }`, `{ dt: 0, tempo: 120 }`, `{ dt: 0, time: [3, 4] }`, `{ dt: 0, key: [-1, 0] }`, `{ dt: 0, marker: "Verse" }`, `{ dt: 0, lyric: "Hap" }`, `{ dt: 0, raw: [0xf4] }`. It writes bytes with `midi-file`'s `writeMidi` where it can and raw bytes where the case is malformed.
- **Import's internal times are ticks** (integers) until `build.ts` converts them to nominal seconds (`tick / ppq / 2`).
- **Diagnostic counting:** each code is reported once, with a count and the first five bars, through one `createReport()` in `src/import/report.ts`, as sync does.
- **`midi-file` text:** it decodes text meta events byte by byte, so tests compare our text with `Buffer.from(theirs, "latin1").toString("utf8")`.
- **MuseScore fixtures** reuse the musicxml package's `.mscx` sources by path (no copies) and add two new `.mscx` files under `packages/midi/tests/fixtures/`.
