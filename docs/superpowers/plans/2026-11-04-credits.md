# Credits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Four optional credit lines (`composer:`, `lyricist:`, `arranger:`, `copyright:`) parsed, printed, shown by the renderer and exported to MusicXML.

**Architecture:** A new `Line` kind `"credit"` classified in `readDocument` beside `part:`; `ChartParse.credits` collects them; the printer prints them where written; the renderer lifts them out of the body into the header (and the copyright into a foot); the MusicXML score writes `<creator>` and `<rights>`.

**Tech Stack:** Bun workspace, TypeScript strict, Biome, Fallow; linkedom for renderer tests; xmllint for MusicXML schema tests.

**Spec:** `docs/superpowers/specs/2026-11-04-credits-design.md` (approved by Kevin 2026-11-04: PR #125 merged).

## Global Constraints

- Names: `composer`, `lyricist`, `arranger`, `copyright`; any case; closed set, no aliases.
- A credit is a line of its own; the value runs to the end of the line (commas allowed); runs of spaces print as one.
- Allowed anywhere in the chart; repeatable; each line one entry, in written order.
- Error on an empty value (the line stays text): message `composer: needs a value` (role name substituted).
- Warning on `composer: A, key: G` (a directive after the value): message `a credit runs to the end of the line; put key: on its own line`.
- Near-miss warnings on text lines `<word>: value`: `author`, `writer`, `music` → composer; `words`, `lyrics` → lyricist; `arr`, `arranged` → arranger; `rights`, `©` → copyright. Message `not a credit; did you mean <name>:?`, suggestion `<name>: <value>`.
- Canonical form: `<name>: <value>` lowercased name, value trimmed with space runs collapsed, printed where written.
- Credits never change bars, numbering, parts, systems' contents or play order. A credit line ends a system as a text line does (grammar 7.4).
- Renderer copy: "Words and music by X" when composer and lyricist lists are equal and non-empty; else "Music by X" and "Words by Y"; "Arranged by Z"; names joined "A and B", "A, B and C". Copyright lines small at the chart's foot, one per line.
- MusicXML: `<creator type="composer">` … `"lyricist"` … `"arranger"` (in that order, one per entry), then one `<rights>` per copyright line, before `<encoding>`.
- Test first; Fallow clean; CHANGELOG entry per package; conventional commits with no AI trailer; grammar change updates the draft and its decisions log in the same commit.

## Review Focus

1. A credit after bars, between sections and at the foot: it must not move, end a section, or warn.
2. A credit inside a run of labelled lines (several parts): it ends the system like text; no part goes tacet because of it.
3. `extractPart` and `transposeChart` keep every credit line unchanged (a transposition must not touch `composer: Bb Music`).
4. A text line that merely starts with a credit-like word and no colon (`Words and music by Kevin`) stays text with no warning.
5. Renderer escaping: a credit with `<`, `&` or quotes is escaped in the header and foot.

**Files:**

**Interfaces:**
- Produces: `type CreditRole = "composer" | "lyricist" | "arranger" | "copyright"`; `CREDIT_ROLES: readonly CreditRole[]` in that order; `Line` member `{ kind: "credit"; line: number; role: CreditRole; text: string }`; `type Credits = Record<CreditRole, string[]>`; `ChartParse.credits: Credits` (every key present, empty arrays when none).

- [ ] **Step 1: Write the failing tests** — `credits.test.ts`, each a `parseChart` call:
  - `"# T\ncomposer: Kevin Peckham\n| G |"` → `credits.composer` equals `["Kevin Peckham"]`, other lists `[]`, no diagnostics; the line has `kind: "credit"`, `role: "composer"`.
  - `"COMPOSER: A\ncomposer: B"` → `["A", "B"]`.
  - `"| G |\ncopyright: © 2026 K\ncopyright: All rights reserved."` → copyright `["© 2026 K", "All rights reserved."]`, no diagnostics, `bars` length 1.
  - `"composer:   Lennon,   McCartney  "` → `["Lennon, McCartney"]`.
  - `"composer:"` → error `composer: needs a value`, line kind `text`, credits empty.
  - `"composer: A, key: G"` → credit `"A, key: G"` and warning `a credit runs to the end of the line; put key: on its own line`.
  - near misses: `"author: X"` → warning `not a credit; did you mean composer:?`, suggestion `composer: X`; likewise `music`, `writer`, `words`, `lyrics`, `arr`, `arranged`, `rights`, `©`.
  - `"Words and music by Kevin"` → text, no diagnostics.
  - several parts: `"part: G = Gtr\npart: P = Pno\nG | C |\ncomposer: A\nP | D |"` → no errors; credits `["A"]`; the two labelled lines are in different systems.
