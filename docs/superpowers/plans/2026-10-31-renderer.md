# `@barmark/render` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A second package, `@barmark/render`, turns barmark chart text into an isolated, themeable, accessible HTML bar grid, as a pure function and as a `<barmark-chart>` web component, published from this repo as a Bun workspace.

**Architecture:** Three layers, each tested on its own:
1. **Model** (`layoutChart`): parse the text with `barmark`, walk the document's lines (rows, text, directives, errors are there) and use the played bars only for bar numbers and elision. Output is plain data: what to draw, already resolved (`%` copied, replays filled in, lyrics substituted, letters and numbers assigned). All the musical decisions live here.
2. **Typesetting and speech** (`typesetChord`, `speak*`): from `ChordParts` to display pieces (root, accidental, superscript, bass) and to spoken names.
3. **HTML** (`renderChart`): the model to a Declarative-Shadow-DOM string (or unwrapped, with a stylesheet), plus the CSS (grid per section, wrapping, themes, forced colours, print). The web component wraps the same function.

**Tech Stack:** Bun 1.3.14 workspaces, TypeScript strict, `bun test`, Biome (tabs), Fallow, Playwright (browser tests, dev only), `linkedom` (DOM for unit tests, dev only). No runtime dependencies besides `barmark`.

**Spec:** `docs/superpowers/specs/2026-10-31-renderer-design.md` (the design; binding), which builds on `docs/grammar-v0.1-draft.md`.

## Global Constraints

- Every commit passes `bun run check`, `bun test`, `bun run fallow` from the repo root. Fallow's baseline may not grow: refactor instead.
- `@barmark/render` has exactly one runtime dependency, `barmark` (workspace). Dev dependencies are pinned exactly (`-E`), each version at least two weeks old.
- Nothing in either package throws on any input. Every problem is a diagnostic.
- **Every string from the chart (title, headings, text lines, error source) is HTML-escaped** before it reaches markup or an attribute.
- Conventional commits, **no attribution trailer**. CHANGELOG entries under `[Unreleased]` of the package they touch; FINDINGS.md entries when something surprises us.
- `main` is protected: work happens on a branch, merged by pull request with green CI. Kevin merges.
- Public surface (semver-major to change): `renderChart`, `renderChartUnwrapped`, `stylesheet`, `fontFaceCss`, `RenderOptions`; the CSS variables `--barmark-font --barmark-size --barmark-ink --barmark-paper --barmark-muted --barmark-rule --barmark-accent`; the parts `title meta heading bar chord text bar-number rehearsal`; the element attributes `src theme bar-numbers rehearsal-letters`.

## Decisions this plan makes

1. **Release tags become per package:** `barmark-vX.Y.Z` and `render-vX.Y.Z`. The existing `v0.0.x`/`v0.1.0` tags stay. The release workflow reads the package from the tag prefix. Rulesets and the `npm` environment get the new patterns (Task 10).
2. **`%` is resolved in the model** from the previous drawn cell (recursively), matching the parser's rule, so the HTML layer never sees a simile.
3. **Bar numbers** come from the played bars: a row's number is the `index` of the first `PlayedBar` of the current section occurrence whose `line` is the row's line. Once an `open` event has been passed in play order, every later row's number is `null`.
4. **Inline chart text for the element** is a child `<script type="text/barmark">`; `src` wins when both are present. A `MutationObserver` re-renders on change. `src` is fetched with `fetch` and not cached by us.
5. **Structural HTML tests use `linkedom`**; rendering, layout and accessibility checks that need a real engine use Playwright (Chromium only in CI).
6. **Screenshot comparison is relative:** the hostile-CSS page is compared with a plain page in the same run, never with committed images, so font rendering differences between machines cannot fail CI.
7. **The silence (`--`) glyph** is a filled rest-like bar (a short thick horizontal stroke), spoken "stop"; N.C. is small caps, spoken "no chord".

## Review Focus

1. **Markup injection:** a title `Tom & Jerry <3`, a heading `## <script>`, a text line `"quoted" & <b>`, an invalid line `| <img onerror=x> |` must render as visible text, never as markup. (Task 5.)
2. **Several charts on one page:** ids used for `aria-describedby` and similar must be unique per chart; the font is registered once however many charts there are. (Tasks 5, 7.)
3. **Degenerate charts:** empty text, a chart of only text lines, only errors, a title with nothing else, a section with no bars that matches nothing. All render without throwing and show what is there. (Task 3.)
4. **A long row on a phone:** `| A | B | C | D | E | F | G | A | B | C | D | E |` at 360 px wide and at 400 % zoom wraps without horizontal scrolling and without shrinking type. (Task 9.)
5. **Open repeat in the middle:** a vamp section (`## Vamp x ...`) followed by more sections: numbering stops after it, and a later replay of a section containing the vamp still draws correctly. (Task 3.)

export type ChartModel = {
	title: string | null;
	header: Directives;              // directives before the first heading
	blocks: SectionBlock[];
	diagnostics: ChartDiagnostic[];

export type SectionBlock = {
	heading: string | null;          // null for content before the first heading

	form: number | null;
	rehearsal: string | null;        // "A", "B", … when the option is on

export type BlockItem =

	| { kind: "directive"; set: Directives }
	| { kind: "error"; line: number; source: string; messages: string[] };
export type CellModel =
	| { kind: "slots"; meter: Meter | null; slots: Slot[]; cut: boolean }
