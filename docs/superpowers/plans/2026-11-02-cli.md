# `@barmark/cli` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `barmark` command (`check`, `format`, `render`, `transpose`) published as `@barmark/cli` and as standalone binaries, then Kevin's public `songs` repository checked by it in CI.

**Architecture:** `packages/cli` is a third workspace package and a thin layer over `barmark` and `@barmark/render`. Every command is a function `(args, io) => Promise<number>` that takes injected I/O, so the tests run commands in-process. Two entry points supply what differs between runtimes: `cli.ts` (Node, from npm) reads the font and versions from the installed packages; `binary.ts` (`bun build --compile`) embeds them.

**Tech Stack:** TypeScript strict, Bun workspace, `node:util` `parseArgs`, `node:fs`, `bun test` with linkedom, GitHub Actions, Swamp.

**Spec:** `docs/superpowers/specs/2026-11-02-cli-design.md`

## Global Constraints

- Package `@barmark/cli`, directory `packages/cli`, bin name `barmark`, release tag `cli-vX.Y.Z`, first version `0.1.0`.
- Dependencies: exactly `barmark` and `@barmark/render`, both `workspace:*` (packed to exact versions). No other runtime dependency.
- ESM, `"engines": { "node": ">=20" }`, MIT, the same `author`/`repository`/`bugs` fields as `packages/render/package.json` (with `directory: "packages/cli"`).
- Commands are real words: `check`, `format`, `render`, `transpose`. Never `fmt`.
- Exit codes: `0` done; `1` chart problems (an error, a warning under `--strict`, a file `format --check` would change); `2` usage or anything unexpected. Never print a stack trace.
- `--version` prints exactly `@barmark/cli X.Y.Z (barmark A.B.C, @barmark/render D.E.F)`.
- No musical logic in the CLI: parsing, printing and transposing come from `barmark`; HTML from `@barmark/render`.
- Charts in folders: `*.chart.md`, recursive, sorted by path, skipping `node_modules` and any folder whose name starts with `.`.
- Commit messages: conventional commits, **no** `Co-Authored-By` or other AI trailer (CLAUDE.md). Every user-visible change gets a CHANGELOG `[Unreleased]` line; surprises get a FINDINGS.md entry.
- Gates before each commit: `bun test`, `bun run check`, `bun run fallow`.

## Review Focus

1. **A chart file with Windows line endings or a BOM:** `check` reports the same line numbers as for LF, and `format --write` writes `printChart`'s output (LF) without a BOM. Test in Task 4.
2. **`format --write` on a chart with an error line:** the file is rewritten with that line kept as written, and the exit code is still 0 (`format` doesn't judge; `check` does). Test in Task 4.
3. **The same file named twice, or a file inside a folder also named:** each chart is processed once. Test in Task 2.
4. **An empty folder, or a folder with no `.chart.md` files:** a mistyped path in CI must not pass silently as `0 files`; exit 2 with `no charts found in <path>`. Test in Task 2.
5. **`--out` pointing into a folder that doesn't exist:** exit 2 with one line, no stack trace. Test in Task 5.
